Host your own BeeMCP

BeeMCP has no database, so your own copy is just a Netlify site, one Beeminder app and two environment variables. It takes about ten minutes and fits in Netlify's free plan.

Type it once you know it (after step 1). Every URL on this page updates to match; until then they show this example. Nothing is sent anywhere.

You'll need:

  • A Beeminder account. Any Beeminder account can register an API app.
  • A GitHub account (to fork the code) and a free Netlify account.

1Deploy the site to Netlify

Do this first. The Beeminder app needs your site's address, and you only get that once the site exists.

  1. Fork github.com/stolati/beemcp to your GitHub account.
  2. In Netlify, choose Add new site → Import an existing project, pick your fork, and click Deploy. Keep every default; the repo's netlify.toml sets the rest.
  3. Optional: under Site configuration → Change site name, pick a nicer name. Your address becomes https://name.netlify.app.

The site is up, but sign-in won't work until you finish steps 2 and 3.

Copy the site address into the box at the top of this page.

Want a custom domain such as bee.example.com? Set it up in Netlify now, before step 2, and use it everywhere below. See Custom domains.

2Create a Beeminder app

This is what users approve on beeminder.com. BeeMCP uses Beeminder's client-side OAuth flow, so it only needs the app's ID, never the secret.

  1. Sign in to Beeminder and open beeminder.com/apps/new.
  2. Fill in the form:
FieldValue
Application nameAnything, e.g. My BeeMCP. Beeminder shows it on its approval screen.
Redirect URLhttps://my-beemcp.netlify.app/oauth/callback
Must match your site address exactly: https, no trailing slash, same hostname you'll connect with.
Post de-authorization callback URLhttps://my-beemcp.netlify.app/oauth/deauthorize
Beeminder calls it when someone revokes the app. BeeMCP only logs it, since there's nothing stored to delete.
Autofetch callback URLLeave empty. BeeMCP doesn't provide autodata.
  1. Save. Beeminder shows the app's client ID and client secret. You can find them again later at beeminder.com/apps.
  2. Copy the client ID. Ignore the secret.
Beeminder allows one redirect URL per app. If you later change your site address, edit the app's redirect URL to match. To use BeeMCP locally or on a second site, create a second Beeminder app.

3Set the environment variables

In Netlify, open Site configuration → Environment variables → Add a variable. Add these with the Functions scope, the same value for all deploy contexts:

VariableWhat to put
BEEMINDER_CLIENT_ID
required		The client ID from step 2. Stray spaces are trimmed. Without it, sign-in stops with "Server is not configured (BEEMINDER_CLIENT_ID)".
TOKEN_SECRET
required		A long random string, at least 32 characters. Use the one generated below and tick Contains secret values in Netlify. This key encrypts every token BeeMCP hands out, so keep it private and don't reuse it elsewhere.
PUBLIC_BASE_URL
optional		Your public address, e.g. https://my-beemcp.netlify.app, without a trailing slash. Normally BeeMCP uses whatever hostname a request arrived on. Set this when the site answers on several hostnames (custom domain plus .netlify.app) so the OAuth metadata and Beeminder redirect always use the one you registered.
BEEMINDER_API_BASE
optional		Don't set this in production. Default: https://www.beeminder.com/api/v1. It exists so the tests can point BeeMCP at a fake Beeminder.

Your TOKEN_SECRET

Here's a fresh one: 64 random hex characters, made in your browser with crypto.getRandomValues. It's never sent anywhere. Copy it into Netlify.

generating…

· Or, in a terminal: openssl rand -hex 32

Prefer the command line? With the Netlify CLI linked to your site:

netlify env:set BEEMINDER_CLIENT_ID "your-client-id"
netlify env:set TOKEN_SECRET "$(openssl rand -hex 32)" --secret
Changing TOKEN_SECRET signs everyone out. Every token already handed to Claude becomes unreadable, and users have to reconnect. That's also your emergency switch if you think the secret leaked.

Redeploy

Environment variables only reach functions on the next deploy. Go to Deploys → Trigger deploy → Deploy site.

4Check it and connect

Open the OAuth metadata in a browser, or run:

curl https://my-beemcp.netlify.app/.well-known/oauth-authorization-server

You should get JSON whose issuer is exactly https://my-beemcp.netlify.app, with authorization_endpoint and token_endpoint on the same host. If the issuer shows a different hostname, set PUBLIC_BASE_URL.

Then add the connector in Claude (Settings → Connectors → Add custom connector) with:

https://my-beemcp.netlify.app/mcp

You should see BeeMCP's approval page, then Beeminder's, with the application name you chose in step 2. If something breaks, check Logs → Functions → oauth in Netlify. Each sign-in step logs one line (consent_shown, beeminder_authorized, token_issued…), and the failing step names its reason. Tokens and secrets never appear in these logs.

Custom domains

  1. Add the domain in Netlify under Domain management and wait for HTTPS to be ready.
  2. Update the Beeminder app's redirect and de-authorization URLs to the new domain.
  3. Set PUBLIC_BASE_URL to https:// plus the new domain, then redeploy.
  4. Users connect with the new /mcp URL. Existing connections keep working because tokens don't depend on the hostname. They only depend on TOKEN_SECRET.

Staying up to date

On GitHub, use Sync fork on your fork to pull in upstream changes. Netlify redeploys automatically when main changes, and your environment variables carry over. Before changing the code yourself, run the tests:

npm install
npm run typecheck
npm test        # full sign-in and every tool, against a fake Beeminder

Troubleshooting

"Server is not configured (BEEMINDER_CLIENT_ID)"

The variable is missing, or you haven't redeployed since adding it. Check that its scope includes Functions, then trigger a new deploy.

Requests fail with a 500, and the log mentions TOKEN_SECRET

TOKEN_SECRET is missing or shorter than 32 characters. Use the generator in step 3, then redeploy.

Beeminder shows an error about the redirect URI

The Beeminder app's redirect URL doesn't exactly match https://my-beemcp.netlify.app/oauth/callback. Look for a different hostname, http instead of https, or a trailing slash. If you use a custom domain, set PUBLIC_BASE_URL as well.

Sign-in works on one address but not another

Beeminder only redirects to the single URL registered on the app. Pick one address, register it, set PUBLIC_BASE_URL to it, and connect only through that address. Deploy previews and branch deploys can't sign in for the same reason.

"Your sign-in session expired or cookies are blocked"

More than 10 minutes passed between BeeMCP's approval page and Beeminder's, or the browser blocked BeeMCP's cookie. Start the connection again from Claude.

Everyone got signed out

Most likely TOKEN_SECRET changed. That includes setting a different value per deploy context, or deleting and recreating the variable. Use one stable value.
